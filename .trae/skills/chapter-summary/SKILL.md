# Chapter Summary

为本项目《Hello-Agents》教材的指定章节生成一份学习总结，写入对应章节目录的 `README.md`，并同步根 `README.md` 的章节索引。严格遵守项目规约（见根 `AGENTS.md` / `.trae/rules/project-rules.md`），尤其是**大白话附录**和**结合最新技术**两条强制要求。

## 输入

- 章节号 N（阿拉伯数字），或章节名。从用户消息里取。
- 若用户没给章节号，先问一句再开始。

## 固定事实（写死，别猜）

- 教材 PDF：`<repo>/Hello-Agents-V1.0.3-20260717.pdf`（在 `.gitignore` 里，不要提交）
- 章节目录命名：`NN-章节名称`，两位数序号，名称取教材章标题
- 总结位置：`NN-章节名称/README.md`
- 根 `README.md` 只做项目说明 + 章节索引，**不写章节正文**
- Python 解释器（本机）：`/Library/Frameworks/Python.framework/Versions/3.12/bin/python3`

## 执行步骤

### 1. 提取章节文本

用本 skill 自带脚本，别自己重写解析逻辑：

```bash
cd <repo>
/Library/Frameworks/Python.framework/Versions/3.12/bin/python3 .trae/skills/chapter-summary/scripts/extract_chapter.py <N>
```

- 输出到 `/tmp/ch<N>.txt`，每页带 `=== p<n> ===` 标记。
- 脚本自动定位起止页（下一章标题前一页）；若定位不准，可传第二个参数（1-based 结束页，含）。
- 脚本只读，不碰项目文件。PDF 里章节数字是康熙部首字符，脚本已用 NFKC 归一化，别自己另写匹配。

### 2. 读文本，梳结构

用 `Read` 分块读 `/tmp/ch<N>.txt`（一次 200 行左右）。先 `Grep` 出所有 `^\d+\.\d+` 小节标题和 `=== p` 页标记，拿到全章骨架，再按需精读重点段落。

### 3. 联网核实最新进展（强制）

按项目规约，**每章都必须**做这一步，不能凭记忆：

- 用 `WebSearch` / `WebFetch` 查该章主题的当前版本、协议标准、产品迭代、已过时/下线的做法。
- 核实版本号和事件时间，写出可追溯的结论。
- 单独成节，标题形如「2025 → 2026：XXX 发生了什么（重要补充）」，与教材原内容明确分开。
- 若无明显变化，写一句「截至整理时该技术保持稳定」。

### 4. 写 `NN-章节名称/README.md`

结构参考已有章节（如 `09-上下文工程/README.md`、`11-Agentic-RL/README.md`），包含：

1. 顶部说明：一句话定位 + 依赖/运行前提（框架版本、需要的服务等）。
2. **0. 一句话记住本章**：一句话点题。
3. 教材正文梳理：按教材小节组织，表格/要点为主，精简不照搬。
4. **「2025 → 2026 变化」一节**：第 3 步的成果，明确标出「教材哪些过时 / 现在怎么做」。
5. **本章总结**速查表。
6. **附录：大白话理解**（强制）：生活化类比，面向初学者，术语紧跟人话解释。

写作要求：
- 精简，讲明白重点，不堆砌。
- 代码片段只放关键骨架，贴完整长代码前先想是否必要。
- 引用项目内文件用可点击绝对路径 Markdown 链接。

### 5. 同步根索引

在根 `README.md` 的章节索引表中，把该行「待补充」改成实际链接和状态说明（框架版本/依赖）。只改这一行，不动其他。

### 6. 收尾

- 若新建了章节目录，确认命名符合 `NN-章节名称`。
- 不要创建额外的 `.md` / README 文档（除本章 README 外）。
- 告诉用户文件路径，并用 `computer://` 链接。

## 注意事项

- 这是本仓库专用 skill，路径硬编码指向本仓库的 PDF 和目录结构；不要拿到别的项目用。
- 章节正文绝不能写进根 `README.md`。
- 「结合最新技术」和「大白话理解」是强制项，缺了不算完成。
- 联网检索失败时如实说明，不编造版本号。
