# 第三章　大语言模型基础

> 本章聚焦「现代智能体的大脑——LLM 是怎么工作的」。主线：语言模型如何演进 → Transformer 架构拆解 → 如何与模型交互（提示/分词/选型）→ 缩放法则与能力边界。
> 本章教材含一个「本地部署开源模型（Qwen）」的动手练习，本项目暂未放置对应代码。

## 1. 语言模型演进：从统计到神经网络
语言模型的根本任务：**计算一个词序列（句子）出现的概率**，判断句子是否通顺。

| 阶段 | 核心思想 | 解决了什么 | 留下的问题 |
|---|---|---|---|
| **统计语言模型 / N-gram** | 用**马尔可夫假设**近似：一个词的概率只取决于前面 n−1 个词；用计数做最大似然估计 | 让概率可计算（Bigram/Trigram） | ①数据稀疏（没见过的组合概率为 0）②泛化差（不懂 `agent` 和 `robot` 语义相近） |
| **神经网络语言模型 + 词嵌入** | 把每个词映射成**连续向量**（Word Embedding），语义相近的词向量也近；用余弦相似度度量，能捕捉类比（king − man + woman ≈ queen） | 解决泛化问题 | **上下文窗口仍固定**，看不到更早的历史 |
| **RNN / LSTM** | RNN 引入**隐藏状态**（短期记忆）让信息沿序列传递；LSTM 用**细胞状态 + 三门控**（遗忘门/输入门/输出门）解决 RNN 的**梯度消失/爆炸**（长期依赖）问题 | 能处理任意长序列、捕捉长距离依赖 | **必须串行计算**，无法并行，训练慢、难扩展 |

## 2. Transformer 架构（现代 LLM 的基石，2017 谷歌提出）
彻底抛弃循环，靠**注意力机制**捕捉依赖，实现真正的并行计算。宏观是 Encoder-Decoder：编码器「理解」整句，解码器「生成」目标句。

核心组件（教材用 PyTorch 自顶向下实现了一遍）：
1. **自注意力 / 多头注意力**：每个词元生成 Q（查询）、K（键）、V（值），用 `Q·Kᵀ/√d` 算相关性 → Softmax 归一化 → 对 V 加权求和。多头 = 让多个「专家」从不同子空间同时关注多种关系（指代、时态、从属等），最后拼接整合。
2. **前馈网络 FFN**：注意力之后，逐位置对每个词元做「先扩大（d_ff=4×d_model）再缩小」的非线性变换，提取更高阶特征；所有位置共享权重。
3. **残差连接 + 层归一化（Add & Norm）**：`Output = x + Sublayer(x)`，解决深层网络梯度消失；层归一化稳定每层输入分布，加速收敛。
4. **位置编码（Positional Encoding）**：自注意力本身不含顺序信息（`agent learns` 和 `learns agent` 对它等价），所以给每个词元向量**加上一个用 sin/cos 公式算出来的位置向量**，注入位置信息。

## 3. Decoder-Only 架构（GPT 的选择）
完整 Transformer 是「先理解再生成」，但 OpenAI 简化为：**只保留解码器，唯一任务就是「预测下一个词」**。
- **自回归生成**：给一段起始文本 → 预测下一个词 → 把它拼回输入 → 再预测下一个，循环直到结束（像文字接龙）。
- **掩码自注意力**：训练时用「因果掩码」把当前位置之后的分数置为 −∞，Softmax 后概率为 0，**数学上禁止模型偷看未来**，保证训练方式与生成时一致。
- **优势**：训练目标统一（适合海量无标注文本预训练）、结构简单易扩展（GPT-4/Llama 千亿参数都基于此）、天然适合生成任务 → 成为通用智能体的基座。

## 4. 与模型交互
### 4.1 提示工程（Prompt Engineering）
- **采样参数**（调整下一个 token 的概率分布）：
  - **Temperature**：控制随机性。T 小→分布陡峭、输出确定（问答/代码/法律）；T 大→分布平坦、输出发散（创意写作）。
  - **Top-k**：只保留概率最高的 k 个候选再归一化（k=1 即贪心采样，完全确定）。
  - **Top-p（核采样）**：从高到低累加概率，取累积达到阈值 p 的最小集合；比 Top-k 更能适应长尾分布。
  - 同时设置时优先级：**温度 → Top-k → Top-p**；通常 Top-k 与 Top-p 二选一。
- **提示类型**：零样本（不给示例）→ 单样本（给 1 个）→ 少样本（给多个，更准确），依赖模型预训练的泛化能力。
- **指令调优（Instruction Tuning）**：用「指令-回答」数据微调后，模型从「文本补全」变成能直接理解并遵循人类指令（今天用的 ChatGPT/DeepSeek/Qwen 都是指令调优过的）。
- **常用技巧**：角色扮演（设定角色引导风格）、上下文示例（给输入输出示范格式）、**思维链 CoT**（加「请逐步思考」，让模型展示推理过程，提升复杂任务准确率且可校验）。

### 4.2 文本分词（Tokenization）
计算机只懂数字，必须先把文本切成 **Token** 再转成数字 ID。
- **为什么不用「按词」或「按字符」**：按词→词表爆炸 + 未登录词（OOV）+ 语义关联缺失（look/looks/looking 被当成三个词）；按字符→词表小但字符无语义、学习效率低。
- **子词分词（主流方案）**：常见词保留整体，罕见词拆成有意义子词。代表算法 **BPE（字节对编码）**：贪心迭代合并语料中最高频的相邻词元对，直到词表达阈值；WordPiece（BERT，按提升语言模型概率合并）、SentencePiece（Llama，把空格也当普通字符，语言无关、编解码可逆）。
- **对开发者的实际意义**：上下文窗口（8K/128K）和 API 费用**都按 Token 计**，不同语言/分词器下 Token 数差异大；模型的某些奇怪表现（如 `2+2` 算不对、大小写影响理解）根因可能在分词，设计提示和解析输出时要考虑。

### 4.3 本地部署开源模型
用 Hugging Face `transformers` 库：`AutoTokenizer` 加载分词器 + `AutoModelForCausalLM` 加载模型 → `apply_chat_template` 格式化对话 → `tokenizer` 编码成 input_ids → `model.generate` 生成 → `batch_decode` 解码回文本。教材用轻量模型 `Qwen/Qwen1.5-0.5B-Chat` 演示。

### 4.4 模型选型（非越大越好，是权衡）
关键考量维度：**性能与能力 / 成本 / 速度（延迟）/ 上下文窗口 / 部署方式（API vs 本地）/ 生态与工具链 / 可微调性 / 安全伦理**。
- **闭源**（前沿、易用 API）：OpenAI GPT、Google Gemini（原生多模态）、Anthropic Claude（长文档/安全可靠）、国产文心/混元/盘古/星火/月之暗面。
- **开源**（灵活、可本地部署与微调）：Meta Llama（Llama 4 用 MoE 混合专家）、Mistral（小尺寸高性能）、国产 Qwen / ChatGLM。

## 5. 缩放法则与局限性
### 5.1 缩放法则（Scaling Laws）
模型性能（Loss）与**参数量、训练数据量、计算量**呈可预测的**幂律关系**——按比例增大三者，性能平滑提升、无明显瓶颈。
- **Chinchilla 定律（DeepMind 2022）修正了「越大越好」**：给定计算预算下，参数与数据存在最优配比——模型应更小、但用多得多的数据训练（70B 的 Chinchilla 用 4 倍于 GPT-3 的数据，性能反超 175B 的 GPT-3），强调**数据效率**。
- **能力涌现**：规模跨过阈值后，突然获得小模型没有的新能力（CoT、指令遵循、多步推理、代码生成）。所以实现复杂自主决策，选足够大的模型是前提。

### 5.2 模型幻觉（Hallucination）——LLM 最关键的局限
模型**过度自信地编造**与事实/上下文矛盾的信息。类型：事实性幻觉、忠实性幻觉（摘要/翻译不忠于原文）、内在幻觉（与输入直接矛盾）。
- **成因**：训练数据含错误；自回归机制只预测下一个词、无内置事实核查；复杂推理中逻辑链出错。
- **其他局限**：知识时效性不足（只知训练截止日前的事）、训练数据中的偏见会被模型吸收放大。
- **缓解方法**：
  1. 数据层：高质量清洗 + 事实知识 + **RLHF**（人类反馈强化学习）
  2. 模型层：新架构 / 让模型表达不确定性
  3. 推理生成层：**RAG（检索增强生成，先检索外部知识库再生成）**、多步推理与自我验证、**调用外部工具**（搜索引擎/计算器/代码解释器）

> 这三点正好对应后面章节的核心设计：用提示词引导规划、按任务选型、在工作流里加验证/RAG/工具调用来规避幻觉。

## 6. 本章关键收获
- 一条演进线：N-gram（统计）→ 词嵌入/RNN/LSTM（神经，解决泛化与长依赖）→ Transformer（注意力，解决并行）→ Decoder-Only + 预训练（预测下一个词，催生 LLM）。
- 与 LLM 打交道的两件事：**提示工程**（引导行为）+ **理解分词**（控制成本/上下文/异常）。
- 对智能体开发的启示：选型要权衡、模型会幻觉且知识会过时，所以需要 RAG、工具调用、多步验证来兜底。
