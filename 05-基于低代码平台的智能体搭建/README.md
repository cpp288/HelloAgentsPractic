# 第五章　基于低代码平台的智能体搭建

> 第四章我们「从零手写」了智能体，懂了原理；第五章切换视角——**站在巨人肩膀上，用图形化平台快速搭、调试、部署**。重心从「实现细节」转向「业务逻辑」。低代码不是要取代代码，而是提供更高一层的抽象，两者可以混合使用。
>
> 说明：本章全部是在 Web 平台上的图形化操作，本仓库未放置对应练习代码。

## 0. 一张表看懂四个平台

| 平台 | 一句话定位 | 最适合的场景 | 开源 |
|---|---|---|---|
| **Coze 扣子编程** | 字节出品，2025 年底升级为 AI 编程驱动的全代码平台；零代码搭原型、全代码做生产都能覆盖 | 快速原型、创意验证、全栈 AI 应用 | 否 |
| **Dify** | 开源企业级全栈 LLM 开发平台（BaaS + LLMOps） | 复杂业务、企业级、多模态 | 是 |
| **FastGPT** | 把 RAG 知识库问答做到极致 | 私有知识库问答、智能客服 | 是 |
| **n8n** | 通用工作流自动化平台，AI 只是其中一个节点 | 深度业务集成、端到端自动化 | 是 |

## 1. 为什么需要低代码平台（5.1）

第四章手写能让你「懂」，但业务一复杂，纯代码的维护成本和开发周期会急剧上升。低代码平台的价值：

1. **降低技术门槛**：把 API 调用、状态管理、并发控制封装成「节点」，产品/业务人员也能参与。
2. **提升开发效率**：数小时甚至数分钟完成原本数天的编码，精力留给业务逻辑和提示工程。
3. **可视化与可观测性**：数据在节点间如何流动、哪步慢、哪步失败，画布上一目了然，比终端日志直观得多。
4. **标准化与最佳实践沉淀**：内置 ReAct 模板、检索引擎、工具接入规范，团队基于同一套组件协作，少踩坑。

> 核心判断：**低代码 = 更高层次的抽象**。它不取代代码，而是把你从底层实现里解放出来。

## 2. 平台一：Coze 扣子编程（5.2）

> ⚠️ **重要更新**：教材基于 2025 年上半年的 Coze 编写，此后产品方向发生了**两次重大调整**：
> - **2025 年 12 月**：「扣子开发平台」正式升级为「**扣子编程**」（code.coze.cn），定位从「低代码 AI Agent 开发平台」转向「基于 AI 编程的全代码应用开发平台」。
> - **2026 年 9 月**：关闭「新建编程项目」入口，统一走「在 Agent 中调用编程开发插件」的模式。
>
> 现在访问 coze.cn 看到的是对话式 AI 产品界面，code.coze.cn 才是开发平台；两者底层能力已经打通。**教材中部分 RSS / GitHub / arXiv 插件已下线，Multi-Agent 模块也于 2025 年 9 月停止支持**，但核心开发骨架未变。

字节跳动出品，从「零代码搭 Agent」进化到「AI 编程驱动的一站式开发平台」，既能像搭乐高一样拖拽插件、配置知识库、设定工作流（低代码），也能让 AI 帮你生成网页/小程序/App 的完整代码（全代码），一键发布到抖音、飞书、微信公众号、豆包等。

### 2.1 平台核心概念（更新版）
- **插件** = 一组工具（技能 + MCP + 可选 Panel 界面），而非教材里简单的「API 集合」。**Panel 是新增**的画布/看板/表格/预览 UI，能让你和 Agent 协同处理同一份内容。
- **MCP 原生支持**（教材中是最大局限，现在反过来）：扣子内置 MCP 客户端，可把任意 MCP Server 封装成自定义插件；官方付费插件本身也能被外部当作 MCP 工具调用。
- **付费体系**：插件商店分为「官方免费 / 官方付费 / 三方免费 / 三方付费」四种，付费按调用量/时长收费；付费插件不能发布到飞书多维表格、掘金等渠道。
- **工作流节点**：基本骨架和教材一致（触发 → 处理 → 条件 → 输出），但 RSS / GitHub / arXiv 这类老插件大多已下线，**改用 MCP 接入对应信息源**。

### 2.2 案例：「每日 AI 简报」助手（教材 5.2.2 案例的新版做法）

教材里的三步（RSS + GitHub + arXiv 插件）现在插件多已失效。推荐两条路：

**方案 A：最快上手——用官方「话题追踪」插件**

扣子官方已提供「话题追踪」插件，核心能力就是「持续监控指定话题的最新动态 → 定期生成简报推送」，本质上是教材案例的开箱版。操作：
1. 插件商店 → 话题追踪 → 添加
2. 告诉它要追踪的话题（如「AI Agent 最新进展」「大模型训练方法」）
3. 设置推送时间、格式和渠道
4. 发布

**方案 B：按教材思路自己搭——插件替换为 MCP**

| 教材里的插件 | 现在替代方案 |
|---|---|
| RSS 插件（36氪/虎嗅/IT之家/InfoQ）| 在 MCP 市场找 RSS / 新闻聚合类 MCP Server 接入 |
| GitHub 插件 | GitHub 官方 MCP Server 接入 |
| arXiv 插件 | arXiv / 论文检索类 MCP Server 接入 |
| 插件直接输出数据 | MCP 返回 JSON → 在工作流里用变量注入 LLM 节点 |

搭建步骤（code.coze.cn 上操作）：
1. **接 MCP 信息源**：Agent 或工作流 → 扩展中心 → 添加 MCP → 分别接入 RSS / GitHub / arXiv
2. **写提示词**：角色=资深科技媒体编辑；System Prompt 定长期格式规范（头条 / 详情 / 推荐阅读），User Prompt 里用 MCP 返回的变量（如 `{{articles}}`、`{{repos}}`、`{{papers}}`）注入
3. **测试调试**：跑一遍看输出，格式不对就回去调提示词、内容不对就换 MCP 源
4. **发布**：一键发布到飞书机器人、豆包、掘金、抖音等渠道

### 2.3 优势与局限（更新版）
- **优**：
  - 原生 MCP（这是教材里的「致命局限」，现在成了长板）
  - 全代码开发能力补齐上限（AI 编程让非技术用户也能产出完整应用）
  - 跨渠道发布便捷
  - Panel 界面让 Agent 能产出可视化成果（看板、表格、画布）
- **劣**：
  - 付费插件体系上线后，部分之前免费好用的插件开始收费
  - 产品方向一年两次大调整，**社区教程和官方文档不同步**（教材就是这个例子）
  - Multi-Agent 模块已下线，需要多智能体协作要用工作流条件分支自己拼
  - 不支持导出标准 JSON 配置文件（只能 Coze 内 zip 互导），版本管理仍弱

## 3. 平台二：Dify（5.3）

开源、模型中立、分层模块化（数据层/开发层/编排层/基础层），融合 **BaaS + LLMOps**，从原型到生产一站式；支持 Docker Compose 一键本地部署（数据隐私）或 SaaS 云。插件市场 8000+，工具丰富度直接决定智能体能力上限。

### 3.1 案例：「超级智能体个人助手」
用「问题分类器」做**智能路由**，把请求分发到不同子智能体（多智能体架构）：
- 日常助手（对话兜底）　文案优化（高频需求）
- 多模态生成（即梦插件生图/生视频，用循环节点拿异步任务结果）
- 数据查询与可视化（`rookie-text2data` 插件连库，给模型喂 DDL/表结构 → 生成 SQL → 大模型整理 → 图表插件出图）
- **MCP 工具集成**：接魔搭/阿里云百炼的 MCP（高德、饮食、新闻），选 ReAct 策略 + SSE 通信模式。

### 3.2 优势与局限
- **优**：全栈一站式、低代码与高扩展平衡好、企业级安全（AES-256 / RBAC / 审计）、工具集成丰富（9000+）、开源社区活跃。
- **劣**：学习曲线仍陡、高并发下性能有瓶颈（核心服务端是 Python）、多模态支持偏弱、企业版贵、API 格式不兼容 OpenAI。

## 4. 平台三：FastGPT（5.4）

定位「**企业级 AI 生产力引擎**」，把**知识库问答（RAG）当一等公民**：围绕「数据导入 → 智能分块 → 向量检索 → 对话生成」全链路深度优化。模型中立，原生支持 MCP。

### 4.1 知识库能力（核心竞争力）
- 支持 Word/Markdown/PDF 导入；两种处理方式：**分块存储** 或 **问答对提取**。
- 精细化配置：分块触发条件（如原文 >1000 字符）、标题入索引、自动生成补充索引、**图片自动索引**（图文混排文档很重要）。
- 透明化调试：能看到每个分块的文本预览和元数据（文件大小、原文长度、处理模式、图片索引状态）。

### 4.2 案例：「智能投顾助手」
- **配 MCP 工具**：实时股票行情 + 图表生成 MCP（来自魔搭 / 阿里云百炼）。
- **可视化工作流编排**：意图识别 → 分支（知识库检索 / MCP 调用 / 风险问卷收集）→ 报告生成。
  - 投资知识教育专员 → 连金融知识库（降低概念问答的幻觉）
  - 风险评估分析师 → 表单节点收问卷（年龄/经验/收入/亏损承受力/目标）→ 大模型出风险画像
  - 市场新闻情报专员 → 调 MCP 取实时数据
- **提示词**：设定专业金融顾问角色，含「不推荐具体产品、不承诺收益」等合规限制，输出结构化报告（风险等级 + 理由 + 风险提示）。

### 4.3 优势与局限
- **优**：RAG 全链路精细控制 + 透明调试、**原生 MCP**、模型中立、可视化 Flow 编排。
- **劣**：模板/预置工具生态比 Coze/Dify 薄、免费版额度紧（100 积分 / 30 QPM）、社区和英文文档仍在完善。

## 5. 平台四：n8n（5.5）

本质是**通用工作流自动化平台**，不是纯 LLM 平台——大模型只是流程中的一个「处理节点」。核心是「**连接**」能力：把孤立的 SaaS、数据库、API、LLM 串成端到端自动化。

### 5.1 两个基本概念
- **节点（Node）**：最小操作单元。分两类——**触发节点**（流程起点，有且仅有一个，如「收到新 Gmail」「定时」「Webhook」）和**常规节点**（处理数据/逻辑）。
- **工作流（Workflow）**：节点连成的自动化流程图，数据以结构化 **JSON** 在节点间传递。

### 5.2 案例：「智能邮件助手」
与传统线性流程不同——`接收 → AI Agent（思考→决策→调工具）→ 回复`，AI Agent 节点把 **模型 + 记忆 + 工具** 整合在一个界面。

1. **建私有知识库**（独立流程，更新知识时跑一次）：Code 节点放知识文本 → Embeddings 节点（Gemini）向量化 → Simple Vector Store 节点写入内存（用唯一 `Memory Key` 当表名）。
2. **主工作流**：
   - Gmail 触发器（Message Received）
   - **AI Agent 节点**：连 Chat Model（思考核心）+ Simple Memory（按 `threadId` 记住同线程往来）+ 两个工具（SerpAPI 联网搜索、Simple Vector Store 查工作时间）
   - 提示词规定：并行搜信息 → 判工作时间加前缀 → 输出严格 JSON（`shouldReply / subject / body`，换行用 `<br>`）
   - Gmail 节点 Send，用 n8n 表达式把字段映射到 JSON 输出

### 5.3 优势与局限
- **优**：开发效率高（数据流画布一目了然）、节点库丰富连接能力强、AI Agent 节点整合优雅、Code 节点兜底自定义、支持私有化部署。
- **劣**：复杂工作流调试繁琐（逐节点查输入输出）、**内置存储非持久化**（Simple Memory/Vector Store 重启即丢，生产必须换 Redis/Pinecone）、版本控制/多人协作不如 git 成熟、超高并发性能不如纯代码。

## 6. 选型建议与「混合开发」（5.6）

| 你的需求 | 优先选 |
|---|---|
| 快速原型验证、非技术用户 | **Coze** |
| 企业级应用、复杂业务逻辑、多模态生成 | **Dify** |
| 基于私有知识库的问答、智能客服 | **FastGPT** |
| 深度业务集成、通用自动化流程 | **n8n** |

**混合开发才是最佳实践**：用低代码平台快速验证想法、处理标准化流程；用代码实现精细化控制和特殊逻辑。两者按阶段灵活切换，而不是非此即彼。

## 附录：大白话理解第五章

> 这一章就一句话：**第四章你是在工地搬砖砌墙，第五章你直接进了「精装修样板房超市」——挑现成的模块拼一拼，房子就起来了。**

### 为什么要从「手写」切到「平台」？
你自己砌墙能学会建筑学，但客户要的是三个月交房。平台把「调模型、存状态、连工具、防死循环」这些脏活封装成一个个**插线板**，你只管把业务逻辑插上电。

### 四个平台像四种不同的「装修套餐」

| 平台 | 装修类比 | 适合谁 |
|---|---|---|
| Coze | 宜家样板间，买回来直接摆 | 不懂装修的人、想快速看效果 |
| Dify | 全屋定制家装公司，材料工人全包 | 要品质、要复杂户型的家庭 |
| FastGPT | 专门做「书房」的专家，书架检索做到极致 | 核心需求就是查资料问答 |
| n8n | 水电布线公司，把所有家电串起来自动联动 | 要让各系统打通协作 |

### 案例里反复出现的「同一套打法」
不管在哪个平台，搭一个能用的智能体都在重复这四件事：

1. **接数据源**：RSS / 数据库 / 知识库 / 邮件——相当于给员工发「资料」。
2. **写提示词**：定角色、定任务、定输出格式——相当于给员工发「岗位说明书」。
3. **接工具**：搜索、MCP、图表生成——相当于给员工配「工具箱」。
4. **连工作流 + 测试发布**：把节点串起来、跑一遍看看、不对就调——相当于「试运营」。

发现没有？这跟第四章手写 ReAct 的骨架（循环 + 提示词 + 解析器 + 记忆）**本质是同一件事**，只是第四章你用代码拼，第五章你用鼠标拖。

### 为什么教材反复强调「别被平台绑死」？
- ~~Coze 不支持 MCP~~ → 教材 2025 年上半年写的，现在 Coze 已原生支持 MCP，但反过来，插件付费化、产品方向大调整又带来新的不确定性；
- n8n 内存存储 → 服务一重启记忆全没；
- 每个平台都有自己的局限（以及自己的「变」）。

所以最聪明的做法是**混合开发**：验证想法用平台（快），核心特殊逻辑用代码（稳）。就像装修可以买成品家具，但水电管线还是得自己设计。

### 一句话记全章
> **手写让你懂原理，平台让你出成品；四个平台各有所长，关键是按场景选、按阶段混合用。**
