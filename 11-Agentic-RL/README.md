# 第十一章　Agentic-RL

> 前面十章我们让 Agent 能想、能查、能协作，但有个天花板没破：**Agent 处理复杂任务时表现不佳**——推理容易错、工具用得笨、不会从错误里学。这一章的答案是 **Agentic RL**：把 LLM 当成可学习的策略，扔进"感知→决策→执行"的循环里，靠强化学习的试错机制，让它自己把推理、工具使用、规划这些能力练出来。
>
> 框架版本：`pip install "hello-agents[rl]==0.2.5"`，底层集成 Hugging Face 的 **TRL** 库，模型选 **Qwen3-0.6B**（0.6B 参数，普通 GPU 能跑）。需要 GPU（哪怕消费级）和 CUDA 环境，纯 CPU 会非常慢。

---

## 0. 一句话记住本章

**SFT 让模型"会做题的格式"，GRPO 让模型"真正会思考"**。前者是模仿训练数据，后者是靠"答对加分、答错不加分"的奖励机制试错，最终能学到比人类标注更好的推理路径。

## 1. 从 LLM 训练到 Agentic RL（11.1）

### 1.1 LLM 训练全景图：两大阶段

一个强 LLM（GPT / Claude / Qwen）的诞生要经历：

```
预训练 (Pretraining)
  └─ 海量文本（数 TB），自监督学习"预测下一个词"
  └─ 学到：语法 + 语义 + 世界知识 + 基础推理
  └─ 特点：数据巨大、成本极高、只学"会说话"

     ↓

后训练 (Post-training) —— 让模型"会做人"
  ├─ ① SFT 监督微调：(prompt, completion) 对，学遵循指令/对话格式
  ├─ ② RM 奖励建模：偏好对比数据 (chosen vs rejected)，学"什么回答更好"
  └─ ③ RL 强化学习：PPO/GRPO 用奖励模型优化，最大化质量同时不偏离原模型太远
```

传统 RLHF 需要大量人工标偏好，成本高；**RLAIF** 用强 AI（如 GPT-4）替代人类标注，效果接近甚至超过 RLHF，成本大降。

### 1.2 核心：PBRFT vs Agentic RL

教材用 MDP（马尔可夫决策过程）五元组 `(S, A, P, R, γ)` 把两者对比得很清楚：

| 维度 | PBRFT（传统后训练） | Agentic RL |
|---|---|---|
| 任务性质 | 单轮对话优化 | **多步序贯决策** |
| 状态 s | 仅用户提示，静态不变 | 历史观察 + 上下文，**随行动演化** |
| 行动 a | 只有文本生成 | 文本 + **工具调用** + 环境操作 |
| 转移 P | 无（单步就结束） | 动态变化（调完搜索工具，状态里多了搜索结果） |
| 奖励 R | **单步**，任务结束才给 | **多步累积**，中间步骤也能给反馈 |
| 目标 | 最大化单步期望奖励 | 最大化**累积折扣奖励** Σγᵗr |
| 思维 | "生成更好的单个回答" | "完成复杂任务" |

举个例子：PBRFT 是用户问"解释强化学习"，模型一次性生成回答再打分；Agentic RL 是用户要"分析这个 GitHub 仓库质量"，Agent 先调 API 拿信息（+0.1）→ 读代码（+0.1）→ 分析合理（+0.2）→ 报告质量高（+0.6），**总奖励 1.0 是逐步累积的**。

### 1.3 六大核心能力

Agentic RL 要教会 Agent 的六件事：

| 能力 | 传统做法的局限 | RL 怎么解 |
|---|---|---|
| **推理 Reasoning** | CoT 靠少样本示例，泛化差；SFT 只能模仿 | 试错学有效推理路径，发现训练数据没有的解法 |
| **工具使用 Tool Use** | 提示工程教死规则 | 学会何时用、选哪个、怎么组合多个工具 |
| **记忆 Memory** | 上下文窗口有限、RAG 是静态检索 | 学会主动管理：记什么、何时更新、何时删 |
| **规划 Planning** | CoT 线性不能回溯；静态模板不适应新情况 | 学会动态规划，愿意先"绕路"收集信息 |
| **自我改进 Self-Improvement** | 不会反思 | 学会识别错误、分析原因、调整策略 |
| **感知 Perception** | 只会文本 | 学视觉推理、用视觉工具、做视觉规划 |

### 1.4 HelloAgents 的四层架构

```
顶层：统一接口层   RLTrainingTool —— 四个 action：train / load_dataset / create_reward / evaluate
  ↓
第三层：训练器层   SFTTrainerWrapper + GRPOTrainerWrapper（封装 TRL，支持 LoRA）
  ↓
第二层：奖励函数层 MathRewardFunction 基类
         ├─ AccuracyReward（答对+1）
         ├─ LengthPenaltyReward（太长扣分）
         ├─ StepReward（推理步骤多加分）
         └─ create_*_reward() 便捷函数
  ↓
底层：数据集层     GSM8KDataset + create_sft_dataset() + create_rl_dataset()
```

### 1.5 快速上手示例（三步跑完完整流程）

```python

# ② GRPO：靠奖励试错优化推理（5 样本）

# ③ 评估
```

## 2. 数据集与奖励函数（11.2）

### 2.1 GSM8K 数学推理数据集

为什么选数学题练推理？三个原因：①有明确正确答案，可自动评估不用人工标；②需要 2-8 步推导，是多步推理的典型场景；③学到的推理能力能迁移到其他领域。

| 项 | 数值 |
|---|---|
| 训练样本 | 7,473 |
| 测试样本 | 1,319 |
| 难度 | 小学 2-8 年级应用题 |
| 推理步数 | 2-8 步 |

### 2.2 三种内置奖励函数（可组合）

| 奖励 | 公式（简化） | 效果 | 风险 |
|---|---|---|---|
| **Accuracy** 准确率 | 答对+1，答错+0 | 简单直接 | 奖励稀疏，训练初期没反馈 |
| **LengthPenalty** 长度惩罚 | 答对才扣 `α·max(0, 长度-目标)` | 鼓励简洁、省 token | 可能抑制详细推理 |
| **StepReward** 步骤奖励 | 答对才加 `β·步骤数` | 鼓励清晰可解释推理 | 可能生成冗余步骤刷分 |

实现细节值得注意：
- 答案提取要处理 `Final Answer:`、`####`、正则取最后一个数字
- 答案比较要容忍 `72.0==72`、`1000==1k`、`"72"=="seventy-two"`
- 长度惩罚和步骤奖励**只在答对时才生效**，否则模型会为了少扣分/多加分而瞎答

常见组合：准确率+长度惩罚（问答系统）、准确率+步骤奖励（教育/可解释 AI）、三者平衡（全面优化）。

### 2.3 自定义数据集和奖励函数

可以用自己的任务数据（只要能定义"答对了没"），继承 `MathRewardFunction` 基类写自定义 `compute_reward()`。

## 3. SFT 训练（11.3）

### 3.1 为什么要先 SFT

GRPO 需要一个"合理的初始策略"才能试错。直接拿预训练模型跑 RL，模型连输出格式都不对，探索空间太大、训练不稳定。所以流程是：

```
预训练模型 ──SFT──▶ 学会推理格式和基础能力 ──GRPO──▶ 真正会思考
```

**SFT 是基础，RL 是提升**。没有 SFT，RL 很难成功；没有 RL，模型只能模仿训练数据。

### 3.2 LoRA：参数高效微调

全量微调 0.6B 模型要更新全部参数，显存吃不消。**LoRA**（Low-Rank Adaptation）只训练一小部分低秩矩阵，冻结原模型权重：

- 显存占用大幅降低（教材给了 Qwen3-0.6B 的显存对比表）
- 训练快、可插拔（一个基座模型可以挂多个 LoRA 适配器）
- 训练完可 `merge_and_unload()` 合并回基座模型部署

关键参数：`lora_rank`（秩，越大表达力越强、显存越高，典型 8/16/32）、`lora_alpha`（缩放系数，通常 2×rank）、`lora_dropout`。

### 3.3 SFT 实战与评估

评估指标：**准确率**（答对比例）、**平均奖励**、**测试样本数**。训练时监控 loss 下降、验证集准确率上升。

## 4. GRPO 训练（11.4）

### 4.1 从 PPO 到 GRPO

**PPO** 是 RL 经典算法，但在 LLM 训练里有三个痛点：①需要额外训练 Value Model，增复杂度和显存；②要同时维护 4 个模型（Policy / Reference / Value / Reward），工程复杂；③训练不稳定，容易奖励崩塌。

**GRPO**（Group Relative Policy Optimization，来自 DeepSeekMath 论文）专为 LLM 设计，核心简化：

```
PPO:   需要 Value Model 估计优势函数 A(s,a)
GRPO:  用"组内相对奖励"代替 —— 同一个问题生成多个答案，
       用 (单个奖励 − 组内平均奖励) 当优势，省去 Value Model
```

| 对比项 | PPO | GRPO |
|---|---|---|
| 模型数量 | 4 个 | 2 个（Policy + Reference） |
| Value Model | 需要 | 不需要 |
| 优势估计 | Value Model | 组内相对奖励 |
| 显存 | 高 | 低 |
| 稳定性 | 易崩塌 | 更稳 |

### 4.2 GRPO 关键参数

| 参数 | 建议值 | 说明 |
|---|---|---|
| `num_generations` | 4-8 | 每题生成几个答案算相对奖励，越多信号越丰富但越贵 |
| `temperature` | 0.7-1.0 | 保持探索性，别用 0（贪婪） |
| `learning_rate` | 1e-5 ~ 5e-5 | 比 SFT 小，不想偏离 SFT 太远 |
| `kl_coef` | 0.05-0.1 | KL 惩罚，太小偏离太远、太大学不动 |
| `clip_range` | 0.2 | 策略比率裁剪，类似 PPO 的 ε |
| `max_new_tokens` | 256-512 | 单答案长度上限 |

### 4.3 训练过程怎么看正不正常

正常信号：平均奖励**逐步上升**、KL 散度保持在合理范围（没爆炸也没塌到 0）。异常信号：奖励突然飙升后崩盘（奖励崩塌）、KL 一直为 0（没学到东西）。

## 5. 模型评估与分析（11.5）

### 5.1 指标体系

- **准确率**：最终答案对不对（核心）
- **平均奖励**：奖励函数打分的均值
- **错误分析**：把错例分类（计算错误 / 推理跳步 / 答案提取失败 / 格式错误），针对性改进

### 5.2 改进方向

教材给的迭代思路：先看错误类型占比 → 调整奖励函数权重 → 增加数据多样性 → 调超参（温度、KL、学习率）→ 必要时换更大基座模型。

## 6. 完整训练流程实战（11.6）

### 6.1 端到端流程

```
1. 准备数据    GSM8K → create_sft_dataset / create_rl_dataset
2. SFT 训练    学格式和基础推理（全量数据，3 epoch）
3. GRPO 训练   从 SFT 模型开始，组合奖励（accuracy+length+step）
4. 评估        测试集准确率 + 错误分析
5. 超参调优    学习率 / batch / KL / 温度
6. 分布式加速  DDP / ZeRO-2 / ZeRO-3 / 多节点
7. 生产部署    LoRA 合并 → 8-bit 量化 → FastAPI 服务
```

### 6.2 分布式训练（显存不够时的出路）

| 方案 | 适用 | 说明 |
|---|---|---|
| LoRA | 单卡也能跑 | 参数高效，优先选 |
| **DDP**（数据并行） | 多卡同模型 | 每张卡一份完整模型，数据切分，总 batch = per_device × 卡数 × 累积步数 |
| **ZeRO-2** | 显存紧张 | 优化器状态分片（省约 1/3 显存） |
| **ZeRO-3** | 大模型 | 参数 + 梯度 + 优化器全分片，省最多但通信开销大 |
| 多节点 | 超大规模 | 主节点 + 工作节点，配 `machine_rank` |

两个易踩的坑：
- **Batch Size 要对齐**：分布式总 batch 要和单卡基准一致，否则效果变
- **学习率线性缩放**：`lr_new = lr_base × √(total_batch_new / total_batch_base)`

### 6.3 生产部署

```python
# ① 合并 LoRA 权重到基座模型
```

## 8. 2025 → 2026：Agentic RL 领域发生了什么（重要补充）

教材以 **GSM8K 数学推理 + Qwen3-0.6B + GRPO** 为教学案例，这在 2025 年是合理的入门选择。但这一年整个领域进展极快，几个关键点必须更新认知：

### 8.1 主战场已从"数学推理"转向"长程工具型 Agent"

教材的场景是"做数学题，答对 +1"——奖励简单、状态短、无外部交互。但 2026 年 Agentic RL 的真正前沿是**长程多步工具使用**：

| 代表工作 | 做什么 | 关键变化 |
|---|---|---|
| **Search-R1**（Qwen 团队） | 让模型学会多轮搜索 + 推理回答开放问题 | 奖励从"答案对错"扩展到**多轮轨迹的过程奖励** |
| **Search-R1++**（arXiv 2602.19526） | Search-R1 的改进版 | 用 **REINFORCE + F1 奖励 + action-level 惩罚**，7B 模型准确率 0.403→0.442 |
| **OpenAI DeepResearch** | 深度研究 Agent | 长 horizon 端到端 RL，ICLR 2026 论文显示在 deep research 基准上领先 |
| **SynPlanResearch-R1**（arXiv 2603.07853） | 用合成计划引导 SFT 冷启动 | 解决"RL 初始化太差导致浅层探索、过早终止"的问题 |

→ **对教材实践的影响**：如果只是学流程，GSM8K 完全够用；如果想跟进前沿，要把奖励设计从"最终答案对错"升级为"**轨迹级过程奖励**"（每一步工具调用、每一次搜索都给反馈）。

### 8.2 GRPO 只是起点，算法家族已经开花

教材重点讲 GRPO（省 Value Model），但 2026 年围绕它演化出一整族变体，各有取舍：

| 算法 | 思路 | 适用 |
|---|---|---|
| **GRPO**（DeepSeekMath） | 组内相对奖励，无 Value Model | 数学推理，教材用的 |
| **DAPO**（字节豆包） | GRPO + 移除 clip、加 token 级 KL、动态采样 | 推理模型，稳定性更好 |
| **RLOO**（Google） | REINFORCE + Leave-One-Out 基线 | 简单基线，易实现 |
| **REINFORCE++** | Search-R1++ 用的 | 配合 action-level 惩罚做长程工具任务 |
| **PPO-lite** / 简化 PPO | 保留 Value Model 但简化 | 部分工程团队仍在用 |

→ 选哪个看任务：数学用 GRPO/DAPO，长程工具任务看 REINFORCE++，别再纠结"PPO 还是 GRPO"了——PPO 在 LLM 训练里基本已被 GRPO 家族取代。

### 8.3 推理模型已成产品，RL-on-CoT 是背后引擎

2025 年你可能听过 **o1 / DeepSeek R1**；2026 年这条线已经全线产品化：**o3、o4-mini（2025-04）、GPT-5（2025-08，自动在快速/深度推理间路由）、DeepSeek R1 / Search-R1**。它们背后的核心 trick 就是教材讲的这套——**用强化学习在 CoT（思维链）上训练**，让模型"学会思考"而不是"模仿思考"。

→ 教材里 Qwen3-0.6B + GSM8K 跑出来准确率很低是预期的；前沿模型用同样的方法论，只是**数据大 5 个数量级、算力大 N 个数量级、任务复杂得多**。方法论你已经在本章掌握了。

### 8.4 训练基础设施的变化

| 教材用的 | 2026 主流补充 |
|---|---|
| Hugging Face **TRL** | 仍是开源训练事实标准，持续更新 GRPO/DAPO 等 |
| 单机 / 单卡 | **vLLM 训练栈**（高吞吐）、**OpenRLHF**（高性能 RLHF）、**TorchTitan**（Meta 分布式） |
| LoRA | 全参数微调在大算力场景回归（前沿模型基本全参）；QLoRA（量化+LoRA）让 70B 也能在单卡训 |
| GSM8K 数学 | 新基准：**Deep Research 系列基准**（搜索+推理+引用）、SWE-bench（代码 Agent）、WebArena / VisualWebArena（网页 Agent） |

### 8.5 更新后的学习路径建议

| 阶段 | 教材路径 | 2026 补充 |
|---|---|---|
| 入门跑通 | GSM8K + GRPO + Qwen3-0.6B | 不变，先把流程跑通 |
| 理解算法 | 看 GRPO 公式 | 同时了解 DAPO / RLOO 的差异 |
| 跟进前沿 | 读 TRL 源码 | 读 Search-R1 / DeepResearch 论文，关注"轨迹级奖励"和"长程工具使用" |
| 自己的任务 | 自定义数据集 + 奖励 | 重点设计**过程奖励**，而非只看最终结果 |

### 8.6 一句话总结这一节

教材教你的是**正确的方法论和最小可运行闭环**（SFT→GRPO→评估→部署），这部分完全不过时；但**任务场景（数学→长程工具）、算法选择（GRPO→GRPO 家族）、评估基准（GSM8K→Deep Research/SWE-bench）** 都在快速演进。把本章的闭环跑通后，想进阶就往"长程多步 + 过程奖励 + 工具使用"方向走——那正是 2026 年 Agentic RL 的主战场。

## 附录：大白话理解

### Agentic RL 到底在干嘛？

想象你教一个**完全靠自学的学生**做数学题：

- **预训练** = 他读了整个图书馆，识字、懂常识，但不知道怎么答题
- **SFT** = 你给他 1000 道题 + 标准答案，让他**照着抄格式**，学会"先写步骤、最后写答案"
- **GRPO** = 你不再给答案了，让他**自己闷头做**，做完你只告诉他"对了"还是"错了"。他做对一次，这种解题思路就被强化；做错，就被削弱。试错几万次后，他自己摸索出了比标准答案更巧的解法

这就是为什么 RL 能"超越训练数据"——**因为它不是在背答案，是在练思路**。

### 为什么 SFT 之后还要 GRPO？只做 SFT 不行吗？

只做 SFT 就像**只让学生抄范文**——他能写出"看起来像那么回事"的文章，但永远是在模仿，遇到没见过的题就懵。

GRPO 是让他**自己做题、自己对答案、自己调整**。代价是慢（要试错很多次）、费钱（每次试错都要算一遍），但收获是真正的能力。

所以教材反复强调：**SFT 是基础，RL 是提升**。地基没打好（SFT 模型输出格式都不对），RL 试错就是在噪音里瞎摸。

### 奖励函数 = 你给学生定的"评分标准"

这是本章最容易出问题的地方。你给什么奖励，模型就学什么：

| 你定的规则 | 模型学到的 |
|---|---|
| 只看答案对不对 | 能答对就行，过程乱写（甚至瞎蒙蒙对） |
| 答对 + 写步骤就加分 | 开始写步骤了，但可能为了刷分写一堆没用的步骤 |
| 答对 + 太啰嗦扣分 | 学会简洁了 |

所以教材才给了**组合奖励**：准确率（必须对）+ 长度惩罚（别啰嗦）+ 步骤奖励（要有条理）。三个一起上，模型才会"又对、又简洁、又有条理"。

**奖励设计是 Agentic RL 的灵魂**——奖励函数写错，模型会"钻空子"（reward hacking），比如发现某个无意义操作能刷分，就一直做那个操作而不是真的解题。

### 多步奖励 vs 单步奖励

单步奖励 = 考试只看最后得分，中间过程不管。
多步奖励 = 做对一步给一点分。

多步奖励的好处是**训练初期也有信号**（不然模型完全瞎猜，一次都蒙不对，就永远学不到东西）。就像教小孩走路，不能等他走完 100 米才鼓掌——迈出第一步就要鼓励。

### GRPO 为什么比 PPO 好？用班级类比

- **PPO** = 每次考试后，老师不仅看分数，还要**估算全班平均水平**，再算你相对平均好多少。这个"估算平均水平"就是 Value Model，得单独训练、单独占显存。
- **GRPO** = 老师不单独估算了，**直接把同一道题让你做 4 遍**，4 遍的分数自己算平均。省去了"训练估算器"这一步，更简单、更省显存、更稳定。

代价是**每题要多生成几遍**（num_generations=4 就是这个意思），计算成本上去了，但工程复杂度下来了——对 LLM 训练来说这笔账划算。

### LoRA = 不换大脑，只贴"便利贴"

全量微调 = 把模型所有参数都改一遍，相当于让学生**重新学一遍所有知识**，又慢又贵还可能把原来会的忘了。

LoRA = 冻结原模型（大脑不动），只在旁边训练一层薄薄的"便利贴"（低秩矩阵）。学到的新东西记在便利贴上，推理时便利贴和大脑一起用。

好处：**省显存、训练快、可插拔**——同一个基础模型，你可以贴一张"数学便利贴"、一张"代码便利贴"，想用哪张挂哪张。部署时 `merge_and_unload()` 把便利贴粘回大脑，就变成一个完整模型了。

### 为什么本章说"跑完准确率低很正常"？

因为教学示例只用了 **10 个样本、1 轮**——相当于让学生做了 10 道题就去考试。真实训练要：全量 7473 个样本 × 多轮 × 多 group × 大模型 × 大量算力。

本章的目的**不是训出一个好模型**，而是让你**亲手跑通"SFT→GRPO→评估→部署"这条完整链路**。理解了这条链路，前沿模型（o3、R1）用的也是同一套，只是规模大得多。
